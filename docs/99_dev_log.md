## 2026-09-11 — '지났다'는 앞범퍼로 잰다 `RED_CLEARING` — 사전주행2 신호25

- **정지선을 이미 지났으면 서지 않는다** — `RED_CLEARING`. 교차로 한복판 정차가 더 위험하다.
  **'지났다'는 앞범퍼로 잰다**(2026-09-11 사전주행2 신호25). 예전 판정(`tl_passed`)은
  **뒷축**이 선을 넘어야 참이라, 뒷축→앞범퍼 3.81m 인 우리 차는 범퍼가 3.0m 넘은 자리에서도
  '아직 안 지났다'가 됐다. 우회전 감속 중 황색을 만나 횡단보도 위에 섰다가 재출발했고, 1초 뒤
  적색이 되자 `RED_STOP` 이 **횡단보도 위에서** 세워 녹색까지 18초를 서 있었다(항목12).
  `tl_stop_dist` 가 0.07m 만 더 줄었어도 빠져나갔을 칼날 위의 판정이었다. 이제 앞범퍼가
  0.3m 넘었고 **아직 굴러가는 중**이면 빠져나간다. 선 차를 적색에 출발시키지는 않는다 —
  그건 항목7 −6 이다. 판정은 그 신호 동안만 물고, 다음 신호로 넘기지 않는다.

## 2026-09-11 — 서 있던 차는 황색에 출발하지 않는다 — 코스 B TRV 신호173

- 황색: '앞범퍼가 정지선에 닿기까지 거리 vs 최대제동거리'로 통과/정지를 가른다
  (`YELLOW_STOP` / `YELLOW_GO`). 뒷축 기준으로 재면 너무 쉽게 '통과'가 된다.
  **서 있던 차는 황색에 출발하지 않는다**(2026-09-11 코스 B TRV 신호173).
  [시행규칙 별표2] 황색등화는 정지선 직전 정지가 원칙이고, 신속 통과는 **이미 교차로에
  일부라도 진입한 경우**뿐이다. 실측: 녹색 내내 횡단 보행자 때문에 정지선 0.96m 앞에
  서 있다가 보행자가 비켜난 순간 출발했는데 0.4초 뒤 황색이 됐다. 그때 0.75m/s ·
  정지선까지 0.53m 였는데 `d_brake` 에 **반응 0.8초**가 들어가 0.66m — 13cm 차이로
  '못 선다'가 돼 그대로 적색에 교차로를 건넜다(사용자: "빨간불에 왜 지나가").
  `yellow_go_min_v`(2.0m/s = 7.2km/h) 아래이고 앞범퍼가 아직 정지선 앞이면 무조건 정지다.

## 2026-09-11 — '멀어진다'가 곧 '다 건넜다'는 아니다 `CW_PED_LEAVE_LANES` — 코스 B TRV

**'멀어진다'가 곧 '다 건넜다'는 아니다**(2026-09-11 코스 B TRV). 횡단보도 정지 판정에서
멀어지는 보행자를 횡 3m 만 넘으면 바로 뺐더니, 왕복 6.5m 차도를 건너던 사람이 아직
횡단보도 위인데 우리가 출발해 42km/h 로 그 옆을 지났다(사용자: "사람이 횡단보도를 다
지나가야 움직여야지 반 지나가자마자 움직이노"). 이제 **내 차도를 벗어나 한 차로 더**
나갈 때까지 센다(`CW_PED_LEAVE_LANES`) — 차도 가장자리는 차로계획(`l`·`r`)이 안다.
상한은 종전대로 `CW_PED_LAT_MOVING`(9m)이라, 다 건너간 사람을 붙잡아 교착되지 않는다.

## 2026-09-09 — VRU 회귀 3판 추가 — 굴러가는 자전거를 못 지나간다

사용자 지적: "실제 대회장에 자전거·휠체어가 나오면 **긴급제동이나 회피를 할 수 있는지
확인을 못 했다**." 맞는 지적이었다. 2026-09-02 에 `vtd_io.is_vru()` 로 분류를 통일하고
카탈로그 222개를 `test_person_class.py` 로 전수 검증했지만, **그 뒤로 휠체어·자전거가
등장하는 주행 회귀 판이 하나도 없었다.** 분류가 맞는 것과 그 분류로 차가 제대로
움직이는 것은 다른 문제다.

기존 판의 취약대상은 전부 **성인(H 1.7~1.8)** 이거나(`jaywalk_v6`,
`hz_jaywalk_occluded`, `ped_crossing`, `school_zone`) **옆 차로를 지나가는**
자전거(`hz_cyclist`)였다. 옛 판정식 `높이 >= 1.2 = 사람` 에서 떨어졌던
휠체어(H 0.92)·자전거(H 1.10)가 **내 차로를 막는** 판은 없었다.

카탈로그 실측 치수(`reference/vtd_2025.2_models.txt`)로 3판을 만들었다.

| 판 | 무엇 | 결과 |
|---|---|---|
| `vru_wheelchair_stop` | 내 차로 한복판에 **정지한 휠체어**(1.01 x 0.62 x 0.92) | ✅ 100 — 옆 차로로 옮겨 통과, 최소거리 3.3m |
| `vru_wheelchair_dart` | 갓길의 휠체어가 42m 앞에서 **차도로 진입**, 편도 1차로 | ✅ 100 — x=127.5 에서 `YIELD_PED` a=-5.0 급제동, x=143.1 정지 후 `PED_LEAVING` 재출발 |
| `vru_bicycle_slow` | **내 차로를 4.5m/s 로 굴러가는 자전거**, 제한 13.9m/s | ❌ **85 (목표 미도달)** |

즉 **정지한 VRU 회피도, 뛰어드는 VRU 긴급제동도 된다.** 안 되는 건 하나다.

### 안 되는 것 — **느리게 움직이는 것**을 영영 추월하지 못한다

`vru_bicycle_slow` 실측: 왼쪽 차로가 통째로 비어 있는데(차로계획 `l=4.95`)
자전거 뒤 **15.4m 에서 16km/h 로 끝까지 따라갔다.** 45프레임 전부 `NARROW_BLOCK`,
횡오프셋은 처음부터 끝까지 `off=+0.0` — **우회를 시도조차 하지 않는다.**

**자전거만의 문제가 아니다.** 같은 판에서 막는 것만 승용차(4.4 x 1.8 x 1.4)로
바꿔 돌렸더니 결과가 같았다 — 16.6m 뒤에서 40초, **미완주**. 50프레임 `NARROW_BLOCK`.
즉 진짜 규칙은 "VRU 를 안 추월한다"가 아니라 **"움직이는 것은 무엇이든 안 추월한다"**
이고, 자전거는 그 규칙이 가장 아프게 드러나는 경우일 뿐이다. (이 진단판은 저장소에
남기지 않았다 — 회귀로 지킬 동작이 아니라 원인을 가르려고 한 번 돌린 것이다.)

두 갈래 길이 **각각 따로** 막고 있다. 둘 다 실측 사고 뒤에 일부러 넣은 방어다.

1. **추월 FSM** — `overtake.py:201` 의 `spd > 1.0` 에서 먼저 빠진다(움직이는 것은
   ACC 담당). 설령 통과시켜도 `overtake.py:216` 의 `_is_vru()` 가 다시 뺀다.
   그 주석의 근거는 2026-08-26 코스 A 다: 횡단보도 위 **정지** 보행자를 추월 대상으로
   잡아 8.7m 앞에서 우측 우회를 커밋했다가 **180초 정지·접촉 57프레임**.
2. **차로단위 회피(nudge)** — `drive.py:1161` 의 `if is_ped and _spd > 0.5: continue`.
   그리고 그 앞단 `ped_ahead`(`drive.py:1784`)도 `row[2] < 0.5` 로 **정지한** VRU 만
   담는다. 이것도 의도다 — **횡단 중인 사람은 비켜 가는 게 아니라 서야 한다.**

그래서 굴러가는 자전거는 두 규칙의 **틈**에 빠진다: 움직이니 nudge 대상이 아니고,
VRU 라 추월 대상도 아니다. 승용차는 1 번 하나만으로 충분히 빠진다. 남는 건 차체 안전망뿐이고, 그건 `body_gap_ped`(1.2m)를
못 벌리니 자전거 속도로 묶는다. 자차는 멈추지 않으므로 `_stalled_since` 도 안 서고
`stuck_long` 탈출도 영영 안 열린다 — **자력 복구 경로가 없다.**

### 왜 지금 안 고쳤나

문턱 하나 바꿔서 될 일이 아니다. 추월 FSM 의 `WAIT -> PASS` 는
(`overtake.py:398~405`) **막는 차가 멈춰 있어야** 열린다:

```
elif ego.speed < 1.5:
    t0 = self.still_since.get(bid)
    if (not traffic) or (t0 is not None and now - t0 > self.stopped_hold):
        self._enter_pass()
```

굴러가는 자전거는 `still_since` 가 영영 안 생기고 자차도 1.5m/s 아래로 안 떨어진다.
즉 '서지 않고 옆으로 나가 지나친 뒤 복귀'는 이 FSM 에 **없는 기동**이다. 새로 만드는
일이고, 이 파일은 그 시도로 이미 네 번 깨졌다(아래 [미해결 ①] 참고).
**대회 3일 전에 손댈 자리가 아니다.**

고친다면 설계는 이렇다 — FSM 이 아니라 이미 회귀로 검증된 `ped_bypass` 경로를 넓힌다:
**① 나와 같은 방향으로 ② 0.5~7m/s 로 굴러가는 ③ 내 차로 안의 VRU** 에 한해,
**④ 같은 방향 옆 차로가 통째로 비어 있을 때만** 차로변경으로 지나간다. ①이 핵심이다 —
빼면 횡단하는 사람을 비켜 가게 되고, 그건 지금 규칙이 일부러 막고 있는 것이다.

## 2026-08-30 — lattice — `lat=IDLE` 은 고장이 아니다

`LATTICE=active` 로 켰는데 한 판 내내 `lat=IDLE/0` 만 찍히는 게 **정상인 경우가 있다.**

`active` 는 FSM 이 **실제로 횡기동 중일 때만** 조향을 넘겨받기 때문이다.

```python
lattice_request = (ov_state in ("PASS", "RETURN")   # 추월 중
                   or nudging                        # 장애물 회피 |nudge| > 0.05
                   or (ov_state == "WAIT" and abs(off - d_ego) > 0.20))
```

**증거는 로그 안에 있다 — `off` 칸이 계속 `+0.0` 이면 기동이 0회였다는 뜻이다.**

1. **경로에 이미 들어있는 차선변경은 lattice 가 안 건드린다.** route 가 그 차선을 따라
   그려져 있어 `off` 는 0 을 유지한다. lattice 는 "경로 **밖으로** 비켜나는" 동작만 맡는다.

   이 `target = 0.0` 으로 만들고 선다(그 자리로 가라 하면 차체 안전망이 우리를 세우고
   아무도 물러서지 않는 교착이 된다 — 2026-08-18 실측 250초 정지). 막힌 자리일수록
   `nudging=False` 다.
3. 그 판에 추월도 넛지도 안 일어났다.

그래서 `shadow` 는 게이트를 무시하고 매 프레임 돈다. 진단 모드가 진단을 못 하면 의미가 없다.

### ① 도로를 달리는 이륜차는 '차'로 본다 [법 제27조]

VTD 는 보행자도 자전거도 오토바이도 전부 **2.0×0.6×1.7** 로 준다. 그래서 옆차로를
달리는 오토바이가 전부 '보행자'였다:

```
#2 t=289.2 (1186,93)   경로횡 +3.4m(옆차로) · 16.8m/s = 60km/h → YIELD_PED  30→10km/h
#8 t=631.0 (1289,-309) 경로횡 -3.6m(옆차로) · 11.4m/s = 41km/h → 30.7→8.5km/h
#9 t=688.4 (1188,-574) 경로횡 +2.7m(대향)   · 방위차 -177°     → 완전정지 a=-5.00
```

**보행자는 60km/h 로 못 간다.** 제27조는 '횡단하거나 횡단하려는' 보행자 보호다 —
나란히·마주 달리는 이륜차는 횡단자가 아니라 교통이고, 그건 ACC·CPA·차체 안전망이
담당한다. → **양보(정지) 규칙에서만** 뺀다:

```python
if two_wheel and not small:            # 자전거·오토바이(진짜 보행자는 small=True)
    riding = (ospeed > 8.0             # 29km/h 넘게 달린다  또는
              or _adh < 25 or _adh > 155)   # 나란히 / 마주 달린다
    if riding and abs(fy - lane_offset) >= lane_half + 0.3:   # 내 차로 밖
        is_ped = False
```

- 옆여유 1.2m 안전망(`body_gap_ped`)은 **그대로** 간다.
- **내 차로 안**의 이륜차는 여전히 사람처럼 다룬다(느린 자전거 뒤를 따라간다).
- **가로지르는** 자전거(방위차 90°)는 그대로 양보 대상이다.

### ③ 정차 표시등 — **비상등은 VTD 에 없다**

사용자 요청은 "종료 시 멈추면 비상 깜빡이도". 3 을 보내 봤고(주행이 끝난 4초 구간이라

```asm
ControlApplier::mapTurnSignalFlags(unsigned char):     ; libHLVTD.so.1.0.0
    mov eax,1 ; cmp dil,1 ; je ret                     ; ts==1 -> 1 (좌)
    xor eax,eax ; cmp dil,2 ; sete al ; add eax,eax    ; ts==2 -> 2 (우), 그 외 0
```

**0/1/2 외의 값은 전부 소등**이다. 프로토콜상 양쪽 동시 점등이 표현 불가능하다.

→ 정차 중에는 **우측 지시등을 켜 둔다**(`GOAL_STOP_SIG`, 기본 `TS_RIGHT`; 0 이면 소등).

그리고 객체의 **`hdg` 가 그 정지선이 세우는 차량의 진행방향**이다(실측: road 30 t=-1.5 →
hdg 0, road 62 t=+4.5 → hdg π). 내 방향과 같은 것만 쓰면 **건너편 선(180°)과 교차로
선(90°)이 한 번에** 걸러진다 — 거리로 어림짐작할 필요가 없다.

**④ 본체 좌표도 같은 버그였다.** 정지선만 고치고 횡단보도 본체는 여전히 `lane_center` 로
찍고 있었다. road 2574 의 두 횡단보도는 `t=+1.39`(기준선 **왼쪽**)인데 저장 좌표는 -1 차로
중심이라 반대편으로 밀렸다. 전체 본체가 **중앙값 2.28m, 최대 10.80m** 이동했다.

그리고 **연속 횡단보도**. 30m 안 연속쌍이 5곳인데 뒤엣것은 **자기 정지선이 없다.**
특히 `road 2311 → 3464` 는 사이가 교차로라 거기서 또 서면 **교차로 안 정차**[법 제32조]다.
제27조⑦이 정지선을 정지 위치로 못박으므로, **정지선 하나를 공유하면 한 번 서는 것으로
둘 다 만족**한다. 자기 정지선을 가진 횡단보도는 건드리지 않는다.

| 코스 A (실측) | 구현 전 | ① | ②로 다시 셈 | ③ | ④ |
|---|---|---|---|---|---|
| 조문 기준 충족 | **0** | (24 "정지") | **12 / 24** | 22 / 23 | **23 / 23** |
| 내역 | — | — | — | — | 정지선 18 + **공유 5** |

⚠️ **출발지점 1곳은 판정에서 뺐다.** ego 스폰 (851.2,-17.2) 에서 `road 173 s=240` 까지
앞범퍼 기준 **3.6m** — **정지선 위에서 출발**하는 셈이라 설 자리가 없다. 고칠 수 없는 것을
위반으로 세면 영구 감점으로 남는다. (전방 카메라 첫 프레임에도 횡단보도가 바로 앞에 찍힌다.)

⚠️ **비용이 100초 남짓이다.** 코스 A 는 경로 전체가 보호구역이라 극단적인 경우다.
제한시간이 있다면 정면으로 부딪히는데, **있는지조차 확인이 안 됐다**(위 '제한시간' 항목).

⚠️ **채점기도 같은 규칙을 안다.** 자기 정지선이 없어 앞선 정지로 충족된 곳은

## 2026-08-20~24 — 점멸 신호 · 고아 정지선 · 정면 접근

전부 **VTD 실주행에서 처음 확인**된 것들이다. 셋 다 "우리 코드가 그 상황을 아예 모르고
있었다"는 종류라, 몰라서 못 지킨 것이지 잘못 지킨 게 아니었다.

### 점멸 신호 — `FLASH_STOP`

`TL_FLASH`(state 6)는 정의만 돼 있고 **아무 데서도 안 쓰였다.** 실측: 코스 A 의
`tl 117` 을 **30.0km/h 로 그냥 통과**했다.

> **시행규칙 별표2** · 적색 점멸: 정지선·횡단보도가 있으면 그 직전, 없으면 교차로 직전에
> **일시정지한 후** 다른 교통에 주의하며 진행할 수 있다. / 황색 점멸: 주의하며 진행.

⚠️ **9910 은 점멸의 색을 안 준다**(state 6 하나뿐). 지도로도 못 가른다 — 실측 2026-08-20:
신호 646개가 전부 `0.40x0.41m` 로 같고 type(1000008/1000012/1000020)도 점멸 여부와 무관하다.
그래서 **서는 쪽**을 택했다. 서면 적색 점멸을 만족하고, 황색 점멸이라도 위반이 아니다.
반대로 안 서면 적색일 때 그대로 위반이다. 신호 id 단위로 **한 번만** 선다.

실차 확인(2026-08-24): `tl=117/6 [FLASH_STOP]` → 30km/h 에서 감속 → 정지 → 통과.

### 고아 정지선 — `STOPLINE_STOP`

우리가 보던 정지선은 **신호 정지선(tl_map)** 과 **횡단보도에 붙은 정지선** 둘뿐이라,
어디에도 안 붙은 도색 정지선은 **존재 자체를 몰랐다.** 사용자 지적 "정지선 무시".

실측: 코스 A 경로 위에 그런 정지선이 **6곳**. 가장 가까운 신호등이 30.7~201.7m,
가장 가까운 횡단보도도 15m 밖이라 신호용도 횡단보도용도 아니다.

> **시행규칙 별표6, 노면표시 530 '정지선'** — 차가 **정지하여야 할 지점**을 표시

⚠️ **표지판(일시정지) 유무는 xodr 로 확인하지 못했다.** 도색만 보고 서는 것이라 과잉일 수
있다. 다만 과잉이면 불필요한 정지일 뿐이고, 안 서는 쪽이 틀리면 위반이다.
공식 v1/v7 코스에는 **0곳**이라 18판 회귀에 영향이 없다(WP9 는 5곳).

⚠️ 도색은 **차로마다** 있다. 옆차로 것이 3m 옆에 같이 잡혀 6곳이 9곳으로 보였다 —
같은 자리(6m 안)는 함께 소진한다.

실차 확인(2026-08-24): `(1397,-348)` `(1059,-347)` 두 곳에서 `STOPLINE_STOP`.

### 정면 접근 — `HEADON_STOP`

앞차 ACC 는 **같은 방향으로 멀어지는 차**를 전제한 식이다. 정면에서 오는 차는 접근속도가
두 속도의 합이라 그 식으로는 너무 늦게 선다. 실측(오프라인 `hz_wrongway`):
8m/s 로 마주 오는 차 **6.72m 앞에 정지** — 접촉은 없었지만 추월 개시에 필요한
`front_overhang 3.808 + 차길이/2 2.2 + margin 1.0 = 7.008m` 에 **0.29m 가 모자라
85초 동안 `OVT:WAIT` 로 갇혔다.**

두 가지로 고쳤다.
1. **접근속도로 판정.** `behavior` 의 경량 객체에는 heading 이 없다(AttributeError 로 확인).
   정지물은 접근속도 = 내 속도, 같은 방향 앞차는 그보다 느리다 — **내 속도보다 빠르게
   좁혀오면** 마주 오는 것이다. 그러면 앞차 ACC 대신 `obstacle_gap`(15m)을 두고 선다.
2. **남은 거리를 내 몫으로 나눠 쓴다**(내속도 ÷ 접근속도). 이게 없으면 15m 를 목표로
   잡아도 상대가 계속 다가와 실제로는 8m 에 선다.

⚠️ **8m 뒤에서는 원리상 못 빠져나간다.** 2.19m 옆으로 빠지려면 최소회전반경 기준 전진이
~5m 필요한데 2.1m 뿐이다. '기어서라도 나가기'(NARROW_CREEP)를 넣어봤지만 물체 쪽으로
기어가기만 했다(8.14 → 6.9m). 답은 **더 뒤에 서기**이고, 그래서 위 ②가 핵심이다.

### 경로 밖 물체가 자차와 겹쳐 투영되던 버그 (대회 치명타였다)

`RouteFrame.project` 가 투영 파라미터 t 를 `[0,1]` 로 **양 끝 구간까지** 가뒀다. 그래서
**경로 시작 60m 뒤**에 있던 차가 `s=0.00, d=0.00` — 즉 **자차와 겹쳐** 투영됐고,
차체 안전망이 0프레임부터 `NARROW_BLOCK` 을 걸어 **최고속도 0km/h 로 출발조차 못 했다.**

지금까지 안 걸린 건 우리 판에 **뒤차가 없었기** 때문이다(객체 최대 4칸, 대부분 앞쪽).
대회에서 뒤에 차가 한 대라도 있으면 그대로 못 움직인다. 양 끝 구간만 t 를 열어
s 가 음수/초과로 나오게 했다 — 중간 구간은 그대로다(거기서 열면 최근접 구간 판정이 무너진다).

### 주변 교통 — `vtd/add_traffic.py` -> `<코스>_TR.xml`

"차들이 반 도로처럼 많이 다니는" 판. VTD 의 교통 생성기를 쓴다 — `<Scenario>` 바로 밑:

```xml
<PulkTraffic><PulkDef CentralPlayer="Ego" Count="50" SemiMajorAxis="400" .../></PulkTraffic>
```

"Pulk"은 무리. **ego 중심 타원에 차를 계속 채우고 멀어지면 지운 뒤 앞쪽에 다시 만든다.**
차마다 경로를 줄 필요가 없어 위의 '달려가 사라지는' 문제가 없다.
기본값은 VTD 의 `Japan_Town_2019` 샘플에서 가져왔다(도심 맵이라 성격이 같다) —
50대 · 승용 62% 밴 11% 트럭 5% 버스 2% **자전거 20%** · 반경 400m.

⚠️⚠️ **PulkTraffic 은 자차 가까이에도 차를 만든다.** 실측 2026-08-24 `_TR` 판:
`[GT 갑툭튀]` 감시가 5건을 잡았는데(최악 **21.7m**, 그때 객체 8개) 전부 t=302~307초,
적신호에서 출발해 교차로를 도는 구간이었다. 지문 추적으로 확인하니 **그 차는 27.9m 에서

##### ① 처음 본 것 — 적신호가 대신 세워주고 있었다

적신호 걸린 판의 로그. 최소 실여유 3.97m 로 **접촉은 아니었다.** 그런데:

**자차가 사람 때문에 선 적이 없다.** `YIELD_PED` 가 속도를 잡은 순간은 있어도 그때 목표가

2. **`|fy|<4.5` 에 들어와야 반응하는 순수 반응형.** 3m/s 로 뛰어드는 사람은 그 창에 들어온
   뒤 **1.4초**밖에 안 남는다(50km/h 기준).

##### ② 1차 수정이 틀렸다 — 감시 폭을 자차 속도로 나눴다

①의 2번을 이렇게 고쳤었다: `reach = 차선반폭 + 사람속도 × 자차도달시간`.
"그 사람이 내가 도착하기 전에 진로까지 올 수 있나"를 본 것인데, **가까워질수록 도달시간이
줄어 감시 폭이 사람보다 빨리 좁아진다.** 자기모순이다.

오프라인 판은 통과했다. **녹색신호로 걸린 VTD 실주행이 잡았다**:

```
13.62    50.4   LANE_KEEP   |  20.4   -8.5  |  5.3  | 16.52m   발동 안 함
```

##### ③ 2차 수정 — 폭은 고정, 방향 대신 **다가오는 속도**로 거른다

| | 전 | 후 |
|---|---|---|
| 정지 목표 | `fx - 6.0` (뒷축) | `fx - 3.81 - 5.0` (**앞범퍼에서 5m**) |
| 전방거리 | 경로 호 길이(`ds`) | `min(호, 직선)` — 호는 직선보다 길어 낙관적이다 |
| 미리 감속 폭 | `1.75 + 사람속도 × 도달시간` (자기모순) | **고정 15m** — 자차 속도로 줄지 않는다 |
| 오탐 거르기 | — | 횡속도 **0.5m/s 이상**으로 진로 쪽에 와야 대상 |

폭만 넓히면 **인도를 걷는 사람마다** 걸린다(유닛테스트가 바로 잡아냈다). 그래서 방향이
아니라 속도를 본다 — 나란히 걷는 사람은 횡속도 0 이라 안 걸리고, 가로지르는 사람만 걸린다.

횡속도는 미분하지 않고 평활값에서 뽑는다. **평활계수를 0.5 로 두면** 정상상태에서
`(평활값 − 현재값) / dt` 가 정확히 실제 횡속도가 된다(`c = r·dt·(1-α)/α`, α=0.5 → `c = r·dt`).
미분 잡음 없이 속도를 얻는 값싼 방법이다.

`PED_CAUTION` 은 서는 게 아니라 접근속도만 깎는다. 하한 2.5m/s 를 둬서 **멀리 있는 사람
때문에 갇히지 않는다.**

#### 해결: 종점에서 선을 넘어가 멈추던 것 (2026-08-19)

"왜 자꾸 끝날 때 선 넘어가서 멈춤?" — 로그를 보니 **종점 2.9m 전까지 50.3km/h**
(`cap_by=PROFILE`)로 달리다 급제동해 **8.9m 지나서** 섰다.

범인은 종점 감속이 **선형 램프**였던 것:

```python
if s_remain < 12.0:
    vp = min(vp, max(0.0, (s_remain - 2.0) * 0.6))   # 12m 지점에서 갑자기 6.0m/s 요구
```

13.9m/s(50km/h)의 제동거리는 21.5m 다. **12m 앞에서 6.0m/s 를 요구해봐야 못 선다.**
정지 프로파일은 선형이 아니라 `sqrt(2·a·거리)` 여야 감속도가 일정하다.

```python
vp = min(vp, math.sqrt(2 * self.GOAL_DEC * max(0.0, s_remain - self.GOAL_STOP_BACK)))
```

| 남은 거리 | 옛 목표속도 | 지금 |
|---|---|---|
| 38m | 50.0 km/h | **49.0** ← 여기서부터 물린다 |
| 20m | 50.0 | 35.1 |
| 12m | 50.0 | 26.7 |
| 4m | 4.3 | 13.9 |
| 1m | 0.0 | 0.0 |

`GOAL_DEC = 2.5 m/s²`(0.25g) 로 38m 앞부터 일정하게 줄인다. **종점 오차 8.4m → 1.1m.**

**18판 회귀로 확인했다**(위 '전체 회귀 18판 — 보행자 + 종점 수정 후'). 이 변경은

늘지 않았다.

실패판은 좌표·시각·접촉수(19799/19801/19808)가 매판 거의 동일하다. 즉 **그 정지차를

신호 위상에 따라 도착 시각이 밀리면 안 만나고 지나갈 뿐이다.

기전(실패판 실측):

```

```

**`NARROW_BLOCK` 이 추월 도중에 차를 세우고, 서는 순간 FSM 이 PASS 를 포기해 오프셋이
무너진다.** 그리고 정지 상태에서 다시 출발해 그대로 박는다. SAT 스윕 때 배운
"정지하면 옆으로 갈 수 없다"와 같은 함정이고, 이번엔 우리 안전망이 스스로 그걸 만든다.
고치려면 **정지가 추월을 취소하지 않게** 해야 한다 — 오프셋은 유지한 채 속도만 0 이어야

#### 해결(2026-08-18): v3 · EV_LEADBRAKE — 정지가 추월을 취소하지 않게

**두 건이 같은 뿌리였다.** PASS 중 `abort_sec`(4초) 넘게 서 있으면 무조건 RETURN 이었는데,
**세우는 건 신호일 수도 있다.** 나가 있는 상태에서 취소하면 차로 중심 = 그 차가 서 있는
자리로 되돌아간다. '멈췄으니 추월을 포기'가 그대로 충돌 명령이 된다.
-> **차로 중심이 아직 막혀 있으면 서 있어도 유지**한다(`overtake.py`). 차로가 비면 취소한다.

추월이 시작됐다가 취소되고 있었을 뿐이다. 같은 자리에서 다섯 번 헛짚었으니 기록해 둔다 —

- `nudge` 는 차량을 건너뛴다(`NUDGE_MAX_DIM` — "차는 추월 FSM 담당")
- 추월 FSM 은 옆 차로가 막혀 `WAIT` — 차로변경을 못 한다

즉 **"차는 FSM 만, FSM 은 차로변경만"** 이라는 분업이 이 상황을 담당자 없이 남긴다.

⚠️ **다섯 번째 실패: '경로 기준 통로판정'(2026-08-17).** `fy` 는 ego 기준(`d_obj - d_ego`)이라
내 횡편차만큼 통로를 넓게 본다. 재출발 직전 횡편차 1.19m 였고, `fy=-3.44` 로 여유 +0.85 라
통과 판정했지만 실제로 지나간 경로기준 횡거리는 -2.25(여유 -0.34)였다. 진단은 맞았고
`min(|fy|, |fy + d_ego - lane_offset|)` 로 고치니 **출발 전에** 좁다는 걸 알아챘다.
그런데 막는 게 **영원히 안 움직이는 정지차**라 서 있는 게 답이 아니다:

#### 미해결 ① EV_COMBO_CHAIN 계열 — 추월 방향을 장애물 쪽으로 고른다

(아래 진단은 유효하다. 갇힘 자체는 풀렸지만 방향 선택 자체는 그대로다.)

한때 "후진이 없어서 못 나온다"고 적어뒀는데 **그건 증상이지 원인이 아니다**(실측 2026-08-17):

```
t=73.9  OVT:PASS 시작   장애물 fx=7.57  fy=+1.07(왼쪽)   clr=+1.39
t=74.2  off = +3.50 (왼쪽으로)                          <- 장애물이 있는 쪽으로
t=75.4  clr = -0.29                                     <- 접촉
t=76.3  정지. 후진이 없으니 그대로 갇힌다
```

`_side_for()` 가 **어느 쪽에 여유가 있나(l/r)** 만 보고 **장애물이 어느 쪽에 치우쳤나**는
안 본다. 좌우 여유가 같으면 무조건 좌측을 고르는데 하필 장애물이 왼쪽이었다.
`_nudge_offset` 은 원래 '물체가 치우쳐 있으면 반대쪽으로'를 하고 있었고 **추월 FSM 에만
그 판단이 빠져 있었다**.

⚠️ **고치려다 네 번 실패했다. 지금은 손대지 않는 게 맞다.** 한쪽을 고치면 다른 쪽이 깨진다:

| 시도 | EV_LEADBRAKE | EV_COMBO_CHAIN |
|---|---|---|
| 현재(커밋) | ✅ 완주 · 접촉 0 | ❌ 갇힘 |
| + prefer(장애물 반대쪽) | 접촉 1904 -> 재실행 시 **갇힘**(불안정) | ✅ 완주 · 접촉 0 |
| + WAIT 정지 | ❌ **미완주** · 접촉 4158 | ✅ 완주 · 접촉 0 |

`prefer` 는 같은 시나리오에서 두 판이 서로 다른 결과를 냈다 — **알려진 실패보다 불안정이
더 나쁘다**. 그래서 17판 회귀로 검증된 상태로 되돌렸다.

근본 원인은 **`nudge` 와 추월 FSM 이 같은 판단을 따로 한다**는 것이다. 하루에 네 번
같은 자리에서 터졌다: ① 블로커 판정 기준(내 위치 vs 차로 중심) ② 회피 방향(여유만 vs
장애물 위치) ③ 정지 책임(FSM 은 속도만 묶고 behavior 는 '차선 밖'이라 빼서, 막혔다고
판단한 차로 10.7km/h 로 굴러갔다) ④ **WAIT 진입 시 두 메커니즘 사이로 빠져나가 아무도
횡을 안 쥔다**(위에서 해결). 개별 수정으로는 서로 밀어낸다 — **횡방향 판단을 한 곳으로
합쳐야** 풀린다.

그 합치기의 **첫 조각이 ④** 였고, 그것만으로 갇힘 두 판이 풀렸다. 남은 조각은
"차로변경 불가 + 차로 안 소폭 회피"의 담당자다(미해결 ①). 대회 뒤에 할 일이다.

#### 해결(2026-08-18): v7 'VTD 붕괴' 의 진범은 **우리 경로 생성기** 였다

증상은 t≈80~100s 에 VTD 출력이 25Hz -> 3.4Hz 로 떨어지고 회복되지 않는 것이었다
(그 구간에서 제어권도 잃어 `vp=0` 을 줘도 0.1m/s² 로만 줄며 목표를 89m 지나쳤다).

**원인: 생성 경로가 검증본 대비 전 구간 한 차로 바깥(3.20m)이라, 연료통을 0.58m 옆으로
스치며 지나갔다.** 경로를 제 차로로 되돌리니 연료통까지 3.32m 가 되고, 회피 기동 자체가
사라지면서(`NUDGE` -> `LANE_KEEP`) 붕괴도 같이 없어졌다.

| | 전 | 후 |
|---|---|---|
| 경로가 연료통에서 | **0.58m** | **3.32m** (8/14 검증본 3.27m) |
| 검증선과의 이격 중앙값 | 3.20m | **0.42m** |
| v7 | ❌ 220~255s · 목표 89m 미달 · 3.4Hz | ✅ **131s 완주** · 접촉 0 · 붕괴 없음 |

버그는 두 개였다.

**① `sample_lane` 이 계획한 차로 번호를 버렸다** (주범)
```python
if cur_t is None:
    if out:  cur_t = min(... 직전 점에 가장 가까운 차로 ...)   # lid 를 안 씀
```
도로 이음매에서 3.1m 튀는 걸 막으려고 '직전 점에 가장 가까운 차로로 붙기'를 넣었는데,
**한 번 어긋나면 끝까지 그 차로를 따라간다.** 그래서 탐색 비용을 고쳐 차로 선택을
바로잡아도 기하는 그대로였다(계획 -1 인데 그려지는 건 -2).
-> 계획한 번호를 **먼저** 쓰고, 그 번호가 그 s 에 없을 때만 근접 스냅.

**② 지정차로 선호가 없었다**
탐색에 '어느 차로가 옳은가' 기준이 없어 연결만 되면 아무 차로나 골랐다.
`LANE_PREF` 로 바깥 차로에 비용을 준다(화살표 위반 500 보다 훨씬 싸게 — 지정차로 때문에
길이 막히면 안 된다). 도교법상 승용차는 왼쪽(안쪽) 차로가 지정차로이므로 감점도 줄인다.

⚠️ **영향은 v7 만이 아니었다.** v1~v6 과 모든 이벤트가 쓰는 `planned_from_xml_v1.json`
도 똑같이 3.20m 밀려 있었다. 통과하던 판들도 **내내 한 차로 바깥으로 달리고 있었다.**

**경로를 만들면 반드시 검증할 것.** 이 사달의 근본 원인은 "생성하고 아무도 확인 안 함"
이다. 최소한 (a) ego 스폰 차로와 일치하는가 (b) 검증선과의 이격 (c) 주요 정지물까지의
거리 — 이 셋은 생성 직후 찍어봐야 한다.

**조사 방법 교훈: "옛날엔 됐다"는 증언이 있으면 가설 소거보다 기준선 재현이 먼저다.**
2026-08-18 에 "지금 설정에서 X 를 바꿔도 무너진다"를 **열세 번** 반복하며 몇 시간을 썼다
(GPU·속도·코어고정·IG개수·페이저스레드·TCP역압·AI차량·연료통개수·회피기동·라이다IP·모델

## 2026-08-20 — 왜 포켓 처리가 이미 있는데도 안 잡히나 — 번호 충돌

`successors()` 에는 이미 '교차로 직전에 새로 생기는 포켓 차로도 이웃이다' 처리가 있다
(WP9 지시위반 3곳을 그걸로 잡았다). 그런데 여기서는 **간선이 아예 안 생긴다.**

`road 2814` 의 laneSection 링크를 보면:

```
진입 s=75.9 : lane 2(w3.77) --pred--> s=72.6 lane3 --pred--> s=0 lane 3   ← 우리가 탄 것
              lane 3(w2.90) --pred--> s=72.6 lane4 --pred--> s=0 lane 4
              s=72.6 lane 2 (w0.97, **여기서 새로 열림**) succ=없음 -> s=0 lane 2 = 좌회전 포켓
```

즉 **좌회전 포켓은 진입 구간에 대응 차로가 없다.** 포켓 간선은 그 차로를 **진출 번호**로

겹친다. 그래서 중복 방지 조건 `same_ex[j] not in here` 에 걸려 **간선이 사라진다.**

**노드의 차로 번호가 '진입 구간 기준'이라는 규약 자체가 이 경우를 표현하지 못한다.**

```
s=230.6  -4(t=-7.5) -3(-4.5) -2(-1.5) -1(+1.6)
```
