# 1장. 문제 정의 — 대회가 요구한 것

[← 문서 목차](README.md) · [README](../README.md)

이 장은 **우리가 풀어야 했던 문제를 주최측 자료 그대로** 정리한다. 우리 해법은 [2장](02_system_design.md)부터 나온다.
출처는 세 가지다 — 대회 안내문(2026-08-27), 주최측 질의응답(주최측 자료라 공개본에는 없다),
대회 당일 공식 평가 화면. 셋이 다를 때는 **평가 화면**을 따랐다.

## 1.2 인터페이스 — 무엇을 받고 무엇을 내보내나

제어PC는 VTD PC와 **랜선 한 줄**로 붙는다. ROS 는 쓰지 않는다 — 전부 raw 소켓이다.

```
 제어PC 192.168.50.10  ──────────────  VTD PC 192.168.50.11
                         9910/TCP   DataPacket 1109B ◀── (ego 자세 · 물체 30개 · 신호)
                         9910/TCP   CtrlPacket    9B ──▶ (조향 · 목표가속도 · 지시등)
                         8554/RTSP  전방 카메라 (읽기 전용)
                         9912/UDP   (허용 포트)
```

| 방향 | 내용 | 비고 |
|---|---|---|
| **받기** | ego `X, Y, Z, heading, pitch, roll` | 위치는 **GT**(잡음 없음). **속도는 없다** — 위치를 미분해 추정 |
| | `objects[30]` — 각 `id, x, y, z, heading, speed, length, width, height` | 수평 80 m 안을 가까운 순으로. **종류 필드가 없다** — 크기로 사람·차·사물을 가른다 |
| | `trafficLight` — `id, state` | 교차로 안에서는 안 준다. ID 보다 **상태값**을 믿으라는 게 주최측 답변 |
| **보내기** | `steering[rad]` · `targetAccel[m/s²]` · `turnSignal` | 지시등은 0/1/2(끔·좌·우)만 받는다 — 비상등은 없다 |

**패킷에 없는 것**이 문제를 어렵게 한다.

- **차선 정보가 전혀 없다.** 어느 차로에 있어야 하는지, 옆으로 비킬 자리가 있는지는 지도(OpenDRIVE `.xodr`)에서 미리 계산해야 한다.
- **정지선 위치를 주지 않는다.** 역시 지도에서 찾는다(주최측도 xodr 사용은 허용).
- **ego 속도가 없다.** 시뮬 시계로 전진하는 위치를 벽시계로 나누면 흔들린다 — 0.3초 창으로 추정한다.
- **9910 은 클라이언트를 하나만 받는다.** 주행 중 다른 프로그램이 붙으면 제어가 끊긴다.

## 1.3 경로 — 대회 당일 좌표로 받는다

코스는 미리 알려주지 않는다. 당일 **USB 로 CSV 한 장**을 받는다.

```
seq,x,y          VTD 월드 좌표[m] — ego 위치와 같은 좌표계
1                출발
2, 3             교차로 1 진입 · 진출
4, 5             교차로 2 진입 · 진출
…
N                종료
```

점만 주고 **그 사이 차로 순서는 주지 않는다.** 교차로 진입·진출이 짝으로 오니 어느 연결로를 타야 하는지는 정해지지만,
어느 차로로 달리다 언제 옮길지는 우리가 계획해야 한다. 15분 안에 계획까지 끝내야 한다.

## 1.4 채점 — 구간당 100점, 15개 항목

| 규칙 | 내용 |
|---|---|
| 구조 | 경로를 **5구간**으로 나눠 **구간마다 100점**에서 시작 → 만점 500 |
| 감점 | **경미 −3 / 중대 −6**. 같은 항목은 **구간당 1회**만. 경미 뒤 같은 항목이 중대로 심화되면 +3 |
| 순위 | **완주 그룹이 항상 위** → 그 안에서 총점 → 완주 시간 → 중대 위반 횟수 |
| 완주 | 주행거리 **2,203.3 m** 도달 (평가 화면 기준) |

평가 화면의 15개 항목과 안내문의 판정 기준을 맞춰 적는다. 이름·순서는 **평가 화면**을 따랐고, 6번만 안내문과 이름이 달라 우리가 대응시켰다.

| # | 평가 화면 항목 | 판정 기준 (안내문) | 등급 |
|---:|---|---|---|
| 1 | 제한속도 준수 | +1 km/h 까지 허용. 초과 1~20 경미, 20 넘으면 중대 | 경미·중대 |
| 2 | 보호구역 속도 준수 | **붉은색 노면** 위에서(후륜축 기준) +1 경미, +5 중대 | 경미·중대 |
| 3 | 차로 유지 | 차선 밟기 1회 경미, 2회 중대 | 경미·중대 |
| 4 | 중앙선 침범 금지 | 0.6 m · 0.6초 이상 침범 | 중대 |
| 5 | 보도 침범 금지 | 0.5 m · 0.3초 이상 | 중대 |
| 6 | 도로 이탈 금지 | 안내문의 '리스폰' 항목에 해당하는 것으로 본다 — 경로 이탈 시 리스폰, 구간당 1회 넘으면 −6 누적 | 중대 |
| 7 | 차로변경 방향지시등 사용 | 차로변경 **3초 전**까지 미점등 | 경미 |
| 8 | 실선 차로변경 금지 | 1회 경미, 2회 중대 | 경미·중대 |
| 9 | 적색신호 정지 | 앞범퍼가 정지선 **2 m 안**에 **0.5초** 정지 | 중대 |
| 10 | 녹색신호 통과 | 녹색에 정지선 30 m 안 **무의미한 정차** 5초 경미 / 10초 중대 | 경미·중대 |
| 11 | 적색점멸신호 일시정지 | 앞범퍼 2 m 안에 0.5초 1회 정지 | 중대 |
| 12 | 횡단보도 정차 금지 | 횡단보도 **위**에서 1 km/h 이하로 3초 | 경미 |
| 13 | 정적 장애물 충돌 | 사물 접촉 | 경미 |
| 14 | 보행자 대응 | 무정차 통과 · 횡단 완료 전 미정차 | 중대 |
| 15 | 도로이용자 충돌 | 차량·보행자 접촉 | 중대 |

## 1.5 주최측이 확정해 준 해석

안내문 문구만으로는 판정이 갈리는 것들을 질의응답으로 못박았다. 답변 전문은 주최측 자료라 공개본에는 넣지 않았다.

| 질문 | 답 | 설계에 준 영향 |
|---|---|---|
| 제한속도는? | 기본 **50 km/h**, **붉은 노면만 30** | 지도의 노면표시 `RM_536`/`RM_518` 도로만 30으로 계산 |
| 저속·정차는 감점인가? | 아니다. 단 녹색 30 m 안 정차는 평가 — **전방 차량·보행자 대응 정차는 면책** | 채점기가 정차 사유에 실제 물체가 있었는지까지 확인 |
| 장애물을 피하느라 중앙선을 넘으면? | **예외 없이 중앙선 침범** — 점선·실선, 장애물 유무 무관 | 기본 주행은 중앙선 너머를 회피 공간으로 쓰지 않는다 |
| NPC 가 끼어들거나 급정지하면? | 그래도 **우리 책임** | 안전거리·충돌 예측을 행동층의 최우선으로 |

## 1.6 요약 — 무엇이 어려운가

1. **지도에서 차로를 스스로 알아내야 한다** — 패킷엔 차선도 정지선도 없다.
2. **좌표 몇 개로 차로 단위 경로를 15분 안에 만들어야 한다** — 코스는 당일 공개.
3. **15개 법규 항목을 동시에 지켜야 한다** — 하나를 지키려는 동작(비키기, 서기)이 다른 항목(중앙선, 녹색 정차)을 깬다.
4. **완주가 점수보다 우선이다** — 막혀서 서 버리면 총점이 높아도 순위가 밀린다.
